# Отчёт о проверках

Статус: MVP реализован, ZIP собран и установлен в пользовательскую папку `mods`. Локальные проверки пройдены. Игровую приёмку выполняет пользователь; по его указанию игру не запускаем.

## Окружение

- macOS, установленная FS25 1.25.1.0, ModDesc 116 — подтверждено пользовательским `log.txt`.
- Официальный опубликованный API: Script v1.20.0.0; исходники установленной версии AI находятся в `dataS.gar`.
- Для локальных тестов используется Lua 5.4.8, собранный из официального архива в `/private/tmp`.

## Выполненные проверки

- **41 локальный тест пройден**: граничные объёмы 0/7599/7600/7920/8000 л; взвешенный расчёт разных ёмкостей; ошибочные, отрицательные и нечисловые данные; точность сравнения; дедупликация fill units.
- На модели штатного AI: штатный `update` сохраняется, перед завершением отсчёта мода проверяется возобновление погрузки; 100% не вызывает расчёт мода; штатная трёхсекундная задержка и её строгое условие окончания; отсутствие повторной фиксации; смена порога; удаление груза после фиксации; повторный вход в ожидание; сохранение проверки запрещённого груза; ограничение на Deliver, single-player и server.
- На модели UI: отдельное создание бегунка без шаблона, размещение только в Game Settings, десять позиций и подписи, обработка выбора, отсутствие дублей при повторном открытии, обновление после смены карты, повторная регистрация фокуса, отключение в multiplayer, очистка при ошибке создания и однократная установка хука. Визуальная отрисовка движка локальной моделью не проверяется.
- На модели XML API: отсутствие файла, восстановление значения, повреждённый XML, значения вне списка, ошибка записи.
- `luac -p` проверяет синтаксис всех Lua-файлов; `bash -n` проверяет `build.sh`.
- `modDesc.xml` проходит `xmllint --schema` по `modDesc.xsd` из установленной FS25.
- Сборщик проверяет CRC архива, включение зарегистрированных Lua-файлов и `modDesc.xml` в корне ZIP. В архиве нет внешней папки, тестов, ТЗ и файлов игры.

## Первая игровая проверка и исправление 1.0.0.1

По пользовательскому логу от 23 ноября мод 1.0.0.0 загрузился с порогом 95%, но UI не появился: `Native volume slider template unavailable`. В 1.0.0.1 убрана привязка к классу и фиксированным индексам дочерних элементов строки громкости; добавлен поиск штатного бегунка по API среди строк настроек. Если подходящего элемента нет, лог содержит ограниченную диагностику дерева меню. Появление строки после исправления ещё требует проверки пользователем.

## Исправление 1.0.0.2

Повторный пользовательский лог подтвердил: `multiVolumeVoice` является обычным MultiTextOptionElement, а не бегунком; поиск существующего бегунка в меню не дал результата. По уточнению пользователя строка перенесена из General Settings в Game Settings. Теперь она создаётся с нуля через `GuiElement`, `OptionSliderElement` и `TextElement`; оформление `fs25_optionSlider` подтверждено файлом установленной игры `sdk/xmlDoku/guiProfiles.xml`. Упаковка включает собственный XML профилей. Появление и поведение бегунка 1.0.0.2 ещё требуют проверки в игре.

## Исправление 1.0.0.3

Лог пользователя подтвердил создание бегунка 1.0.0.2 в Game Settings. При выходе/навигации возникала повторяющаяся ошибка `InGameMenuSettingsFrame.lua:481: attempt to call missing method setImageColor`. Контейнер строки заменён с `GuiElement` на `BitmapElement`, который поддерживает штатную окраску строк меню. Добавлена регрессионная проверка вызова `setImageColor` на зарегистрированных строках. Исправление реального выхода по Esc требует повторной проверки в игре.

Также пользователь сообщил, что Deliver не стартует. В просмотренном логе нет отдельной Lua-ошибки AI; причина пока не установлена. Изменений запуска/валидации Deliver в этой сборке нет.

## Оформление 1.0.0.4

На скриншоте пользователя строка 1.0.0.3 имела белый фон и смещённое вниз значение. Причина оформления: Bitmap-контейнер унаследовал стандартный белый цвет, а профиль текста штатного OptionSlider размещал значение ниже шкалы. Добавлен явный тёмный фон строки из палитры FS25, возвращена высота 50 px, значение вынесено справа от шкалы в той же строке. XML синтаксически проверен; цвета и якоря сопоставлены с установленным SDK. Итоговый вид в игре ещё требует подтверждения.

Свежий просмотренный лог 1.0.0.3 подтверждает добавление строки и не содержит прежних ошибок setImageColor. Это не подтверждает прохождение всех действий меню или запуск Deliver.

## Оформление 1.0.0.5

По обратной связи пользователя подтверждён выход по Esc в 1.0.0.3/1.0.0.4. По запросу возвращены ширина шкалы 270 px и значение под шкалой. Правый край контрола возвращён к штатному отступу -10 px, от которого штатный tooltip рассчитывает положение в правой колонке; сокращённый и сдвинутый влево контрол 1.0.0.4 смещал подсказку на настройки. Убраны фиксированные цвета фона и добавлен вызов штатного `page:updateAlternatingElements(layout)` после вставки строки и при каждом открытии. Метод подтверждён установленным модом Better Contracts; палитра `InGameMenuSettingsFrame.COLOR_ALTERNATING` используется также установленным Universal Autoload. Точная отрисовка 1.0.0.5 ещё требует проверки пользователем.

## Шкала 1.0.0.6

По запросу пользователя доступны ровно 50, 60, 70, 75, 80, 85, 90, 95, 98 и 100% (Vanilla). По умолчанию по-прежнему 95%. UI строит подписи из общего списка допустимых значений; расчёт допускает пороги от 50%. Проверены границы 3999/4000 л для 50% и новые меньшие пороги, все десять вариантов хранения и восстановление ранее сохранённых 95/98/100%. Отображение новой шкалы в игре ещё требует проверки.

## Ожидание окончания погрузки 1.0.0.7

Пользователь подтвердил работу мода, но при 50% прицеп отправлялся во время продолжающейся перегрузки. Изменена семантика ожидания для порогов ниже 100%: каждое увеличение объёма хотя бы в одном участвующем отсеке переносит штатный срок отправления на `g_time + waitDuration`. Проверка выполняется перед исходным update, в том числе в кадре истечения предыдущего срока. Падение ниже порога, повышение порога выше фактической заполненности и недопустимый груз отменяют только отсчёт мода и возвращают штатную проверку. Состояние наблюдения очищается на start/stop/reset.

Добавлены семь регрессионных проверок: непрерывный поток после порога и старого срока, возобновление после короткой паузы, падение ниже порога, повышение настройки, запрещённый груз во время отсчёта, поступление в один отсек при неизменной сумме груза, а также штатное полное заполнение и очистка состояния. Также проверен обход контроля потока при 100% даже при наличии ранее созданного состояния наблюдения. Всего 37 локальных тестов.

Официальный API FillUnit описывает `spec.fillTrigger.isFilling` для загрузки через триггер, но не как универсальный флаг поступления из комбайна: https://gdn.giants-software.com/documentation_scripting_fs25.php?category=78&class=672&version=script . Поэтому используется изменение фактического объёма. Три секунды без роста объёма считаются окончанием загрузки. Игровой тест нового ожидания ещё не выполнен.

## Что не подтверждено

Иконка создана из пользовательского SVG: внешний фон прозрачный. По последующей просьбе пользователя заливка изменена на зелёную #5f7524, надпись — на светло-серую #d6d6d2. Окно кабины и центры четырёх колёс вырезаны в прозрачность, проверена alpha=0 в каждом отверстии после декодирования DDS. Готовый `icon.dds` проверен по заголовку (512×512, DXT5/BC3, без цепочки mipmaps), обратным декодированием и просмотром на шахматном фоне. Угловой пиксель имеет alpha=0, светло-серые детали alpha=255. `modDesc.xml` и ZIP используют DDS; PNG остаётся в проекте для просмотра. Отображение новой иконки в игре ещё не проверено.

**Сценарии доставки, в особенности обязательные 3–6 и 9, не проверены в игре.** Загрузка мода подтверждена пользовательским логом; UI версий 1.0.0.0 и 1.0.0.1 не появился. Модели AI, UI и XML не заменяют GIANTS Engine. Также пока не подтверждены реальный вид и клавиатурная навигация бегунка, сохранение через игровой XML API после полного перезапуска и жизненный цикл меню в игре.

Попытка доступа к приложению через инструмент управления завершилась ошибкой `unknown or expired node_repl continuation`. После неё пользовательский `log.txt` оставался от предыдущего запуска, записей о новом моде не появилось. Затем пользователь поручил выполнить игровые проверки самостоятельно; новых попыток запуска не было. Отсутствие Lua/XML errors при загрузке нового мода **не заявляется**. Старый лог содержит ошибки других модов, они не относятся к этой сборке.

Внутренний код AI версии 1.25.1.0 не сравнен с опубликованным кодом 1.20: доступен только упакованный `dataS.gar`. Проверки наличия классов, методов и полей обеспечивают защитный отказ, но сами по себе не доказывают совместимость жизненного цикла.

## Короткий порядок проверки пользователем

1. Включить мод на тестовой карте. Открыть Game Settings, найти бегунок **AI unloading threshold**, проверить 95% и отсутствие дублей при повторном открытии.
2. Начать штатный **Deliver** с пустым прицепом и включённым повторением. Загружать его уже во время ожидания: игра может сама пропустить ожидание, если запускать Deliver с непустым прицепом.
3. При доступной ёмкости 8000 л и 95%: на 7599 л должен ждать; на 7600 л — начать поездку после штатной задержки; 7920 л также должны запускать рейс.
4. При 100% и 7920 л должен ждать; при 8000 л — отправляться как в оригинальной игре.
5. Проверить выгрузку и возвращение за следующей партией. Изменить 95% на 90% во время ожидания и проверить применение без перезапуска.
6. Перезапустить игру и проверить сохранённое значение; проверить несколько прицепов и повторный вход на карту.
7. После теста изучить `log.txt`: строки `[AIUnloadThreshold]`, Lua errors и XML errors. При проблеме сохранить лог до следующего запуска.

## Исправления по отзыву ModHub — 1.0.0.9 (28 ноября 2026)

- Удалены все пять `pcall` из игровых скриптов. XML-дескрипторы проверяются на nil, параметры сохранения валидируются. Отсутствующие UI-объекты и дочерний slider обрабатываются явно с удалением незавершённой строки. Неожиданные ошибки API больше не подавляются.
- `readUnits` проверяет коллекции, записи, индексы и наличие методов. Два чередующихся буфера сохраняют текущий и предыдущий снимки; массивы и записи переиспользуются. Дедупликация не создаёт таблиц. Новые таблицы нужны только при инициализации буферов и увеличении числа fill units.
- Пройдён 41 локальный тест, включая переиспользование буферов и записей за 1000 чтений, неизменность предыдущего снимка, удаление устаревших единиц, некорректные входные данные, отказ создания XML и видимость ошибок getter. Существующие сценарии погрузки и таймера проходят.
- Синтаксис Lua и сборочного скрипта проверен; ZIP 1.0.0.9 пересобран с проверкой CRC. Игра и официальный TestRunner для этой версии не запускались; повторная сертификация ModHub не выполнялась.


## Размещение в AI Workers — 1.0.0.10 (28 ноября 2026)

- Строка порога размещается сразу после штатной настройки пополнения навоза в AI Workers, перед заголовками других модов. Поиск использует идентификатор штатного контрола, без зависимости от языка и абсолютного индекса.
- При каждом открытии восстанавливается порядок в layout и controlsList. При отсутствии опорной строки настройка не добавляется в чужой раздел; выводится предупреждение.
- Пройдены 43 локальных теста. Новые регрессионные сценарии проверяют добавление чужих строк до/после нашей, повторное открытие, восстановление порядка и отсутствие штатной опорной строки.
- ZIP пересобран с проверкой CRC. Игровое отображение этой версии и идентификатор опорного контрола в установленной версии движка пока не подтверждены; игра не запускалась.
